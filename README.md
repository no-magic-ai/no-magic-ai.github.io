# no-magic-ai.github.io

Static site for the no-magic-ai organization, published by GitHub Pages from `main`. Plain HTML, CSS and browser JavaScript; there is no package manager, bundler or build pipeline.

## Content snapshot

Two committed, same-origin files hold the site's algorithm and paper content:

- `data/content.json` — the website projection of one published cohort.
- `data/cohort.json` — the cohort receipt the projection was built from, copied byte for byte.

Both are generated by `scripts/build_content.py` (Python 3.12 standard library only). It reads committed metadata only: `no-magic`'s `docs/catalog.json`, `no-magic-papers`' generated `data/papers.json` and the `no-magic-viz` scenes and GIF previews the paper cards declare. It does not import or run code from those repositories, parse paper-card YAML or fetch anything.

### Inputs

- `--core-root`, `--papers-root`, `--viz-root`: clean Git worktrees of `no-magic`, `no-magic-papers` and `no-magic-viz`, each checked out at the commit the receipt names.
- `--receipt`: a published cohort receipt (`schema_version` 1, `cohort: published`) written by `no-magic-papers`' `scripts/validate_invariants.py`, for example the `cohort-receipt-published-*` artifact of that repository's `validate` workflow on `main`. The receipt is trusted as the owner-selected record of a validated, published cohort; the builder does not re-run that validation.

Before producing output, the builder requires each root's `origin` to be its `no-magic-ai` repository, its `HEAD` commit and tree to equal the receipt and its tracked files to be unmodified. Every file it reads or links (catalog, `data/papers.json`, each implementation script, paper card, drafted or published lesson, scene and preview) must be listed in the receipt, be a regular non-symlinked file and have exactly the receipt's SHA-256 and committed blob. Catalog and paper fields are checked for exact keys, known enumerations, plain relative paths and absolute `http`/`https` paper URLs without credentials; each catalog script must have exactly one implementation record on the paper card the catalog names. Any failure exits 1 before either output is written.

### Commands

```sh
python3 scripts/build_content.py --core-root ../no-magic --papers-root ../no-magic-papers \
  --viz-root ../no-magic-viz --receipt /path/to/cohort-receipt.json
python3 scripts/build_content.py --core-root ../no-magic --papers-root ../no-magic-papers \
  --viz-root ../no-magic-viz --receipt /path/to/cohort-receipt.json --check
python3 -m unittest discover -s tests
```

The first command writes both files. `--check` rebuilds in memory and exits 1 unless both files exist with exactly those bytes; it never writes. Identical inputs always produce identical bytes. After `no-magic`, `no-magic-papers` or `no-magic-viz` publishes a change, obtain the new published receipt, check out the matching commits and rebuild; until then the site keeps showing the previous cohort.

### `data/content.json` (`schema_version` 1)

UTF-8 JSON with keys sorted at every level and non-ASCII text kept literal.

- `cohort`: `receipt_sha256` (SHA-256 of `data/cohort.json`), `repositories.{no-magic,no-magic-papers,no-magic-viz}.{commit,tree}` and `inputs` binding the projected `docs/catalog.json` and `data/papers.json` (`path`, `sha256`, `blob`).
- `algorithms[]`, sorted by tier then name: the catalog fields `name`, `display`, `tier`, `thesis`, `lines`, `paper_slug`, `teaching_kind`, `data_source`, `adaptation_note` (string or `null`) unchanged, plus `source_path`, `source_url`, `declared_commit` and `declared_release` (the implementation record's historical values, not the cohort commit) and `media` with `status` (`linked` or `omitted`), `note`, `preview_url` and `scene_url` (`null` when omitted).
- `papers[]`, sorted by slug: the card frontmatter `slug`, `title`, `authors`, `venue`, `year` (string), `arxiv_id`, `doi`, `url`, `discovered_via`, `discovered_date`, `status`, `themes.{primary,secondary}`, `tags` and `routing` (the card's routing declaration, a plan rather than shipped code) unchanged, plus `card_path`, `card_url`, `dependencies` (paper slugs), `implementations` (script names) and `lesson` with `status`, `path` and `url` (set only for drafted or published lessons).

Every repository URL is pinned to the cohort commit: `https://github.com/no-magic-ai/<repo>/blob/<commit>/<path>` for scripts, cards, lessons and scenes and `https://raw.githubusercontent.com/no-magic-ai/no-magic-viz/<commit>/previews/<script>.gif` for previews. The snapshot is a derivative of those repositories, not a new metadata authority.

The committed snapshot is built from the published cohort `no-magic` `456e9b5f5944979e3844bd2c8e0066bd73ab52be`, `no-magic-papers` `f0be575ae9bbe75bd787c5b7495d036920ef39d4` and `no-magic-viz` `7a3e9423326a7d0c83e7240b7c967b09ce8ccdf5`. In it, six paper cards have a published lesson (`gpt-1`, `lora`, `dpo`, `kv-cache`, `rope`, `turboquant`) and one has a drafted lesson (`deepseek-r1`); their lesson links point at that `no-magic-papers` commit.

## Serve locally

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

Open `http://127.0.0.1:8000/`. The home, algorithm (`/algorithms/`) and paper (`/papers/`) pages load `data/content.json` through `content.js`, which rejects a snapshot whose shape, enumerations or pinned URLs do not match the description above and then shows an explicit error instead of partial data. Browsing, search and filters therefore work without GitHub API access. Filters live in the address (`?q=…&tier=…&kind=…&theme=…&data=…&adaptation=…` on `/algorithms/`, `?q=…&status=…&theme=…&lesson=…` on `/papers/`); an unrecognized parameter or value is reported rather than ignored.

When a paper has a drafted or published lesson, its paper card shows the lesson's status next to a `Read lesson` link, and its implementing-algorithm cards show a `Lesson (status)` link. Both use `lesson.url`. The first three learning-track cards on the home page (Transformers, Alignment, Modern Inference) are plain links to their sections of the maintained `LEARNING_PATH.md` on `no-magic`'s `main` branch; unlike every snapshot link, they are not pinned to the cohort commit and follow later curriculum changes.

Preview GIFs, scene and source files, paper cards, lessons and paper links are external: previews load from `raw.githubusercontent.com` only when a preview is opened, and every outbound link names its host. They need network access, as do the optional web fonts, the author avatar and the GitHub star and fork counts on the home page. The previews are historical excerpts, not full, current or fidelity-certified renders.

The site has no JavaScript toolchain; check changes in a real browser against the served pages.
